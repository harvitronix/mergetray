# MergeTray workspace wireframe

A standalone, local-only prototype. No build, dependencies, database, model, real terminal, or external integrations. All data is fictional and mutations stay in browser memory until refresh.

From this directory:

```sh
python3 -m http.server 51248 --bind 127.0.0.1
```

Open http://localhost:51248. You can also open `index.html` directly.

## Flows to explore

- **Resume:** Home → Catch me up → Review the pending change → product preview → merge → monitor → simulate deployment → simulate verification.
- **Recursive tasks:** Expand a workstream, open a child, and add a subtask at any level. Search with Cmd/Ctrl+K.
- **Companion:** Switch between task and workspace scope. Try the suggestions, ask where you left off, ask about decisions, or ask to start a coding session. Responses are scripted, not generated by a model.
- **Coding:** Open Sessions → start Codex, Claude Code, or OpenCode → switch conversation/terminal → send a follow-up → finish a simulated turn.
- **Decisions:** Needs you → Handle schedule conflicts → choose warning or blocking behavior. The brief and activity update.
- **External events:** Hooks & automations → send a merge, deployment, session-completion, or Linear-assignment event. Replay a merge to see duplicate protection. Enable the Linear hook before testing assignment.
- **Dev environment:** Click the dev preview status in the bottom bar, start the simulated preview, and open it.
- **Ideas:** Capture an idea without a repository or issue. Add children and sessions later.

Task and workspace companion conversations are separate in this prototype. This is an interaction experiment, not a commitment to separate underlying agents.

Use **Reset demo** in the bottom bar to return to the initial scenario. No real PRs are merged, no processes are started by the UI, and no services are contacted. The Python server serves only this folder.
